================================================= Question 4 =================================================

- Since the switch operates at Layer 2 (link layer) and forwards frames based on MAC addresses, the source device (e.g., PC0) must resolve the destination’s IP address to its MAC address before 
  sending data. This is where ARP comes in

------------------------------------- ARP Process -------------------------------------

- When PC0 wants to ping PC1 (e.g., ping 192.168.1.3), it first checks its ARP cache to see if it already knows the MAC address for 192.168.1.3

- If the MAC address is not in the cache, PC0 sends an ARP request (a broadcast frame) asking, “Who has IP 192.168.1.3? Tell me your MAC address.”

- The switch floods this ARP request to all ports in the same VLAN (e.g., to PC1)

- PC1, recognizing its IP address, responds with an ARP reply containing its MAC address (e.g., 0000.0C78.9ABC)

- PC0 stores this mapping in its ARP cache (IP 192.168.1.3 → MAC 0000.0C78.9ABC)

------------------------------------- Sending the Ping -------------------------------------

- Once PC0 knows PC1’s MAC address, it constructs an Ethernet frame for the ICMP packet: Source MAC, Destination MAC, Payload (IP packet with source IP and destination IP, containing 
  the ICMP echo request.)

- The switch receives this frame, checks the destination MAC address, and forwards it to the port associated with PC1’s MAC address (based on its MAC address table)
